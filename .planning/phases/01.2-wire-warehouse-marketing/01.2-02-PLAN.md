# Plan 02: Marketing — Full-Featured Campaigns

## Objective
Replace mock data with real API for marketing campaigns. Implement campaign CRUD, audience segmentation, message templates, and campaign statistics.

## Context
- `01.2-CONTEXT.md`
- `web/src/pages/MarketingPage.tsx` — current mock implementation
- `backend/app/api/v1/` — existing API patterns

</read_first>

<action>
Create `backend/app/models/marketing.py` with:
1. Campaign model:
   - id (UUID), name (str), description (str, nullable)
   - status (Enum: draft, active, completed, cancelled)
   - start_date, end_date (datetime, nullable)
   - budget (float, nullable), source_code (str, nullable)
   - target_audience (JSON/text, nullable) — stores filter criteria
   - created_at, updated_at (datetime)
2. MessageTemplate model:
   - id (UUID), name (str), channel (Enum: sms, email, telegram)
   - body (str), placeholders (JSON, nullable)
   - created_at
3. CampaignLog model:
   - id (UUID), campaign_id (FK), client_id (FK, nullable)
   - template_id (FK), channel, status (sent/failed/pending)
   - sent_at, error_message (nullable)
</action>

<action>
1. Add marketing models to database initialization (import in models/__init__.py or relevant file)
2. Create `backend/app/api/v1/marketing.py` with:
   - GET/POST `/campaigns` — list/create campaigns
   - GET/PUT/DELETE `/campaigns/{id}` — get/update/delete
   - GET `/campaigns/{id}/stats` — return: order_count, total_revenue, conversion_rate
     (match campaign.source_code with work_orders.source)
   - POST `/campaigns/{id}/send` — execute campaign:
     - Parse target_audience filters
     - Find matching clients
     - Use selected template + channel
     - Create CampaignLog entries
     - Return: sent_count, failed_count
   - GET/POST `/templates` — list/create message templates
   - GET/PUT/DELETE `/templates/{id}` — get/update/delete
3. Include router in main.py with prefix `/api/v1/marketing`
</action>
