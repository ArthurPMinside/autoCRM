# Phase 1.3: Real Analytics Data — Context

## Domain
Replace mock data in Dashboard and Analytics pages with real API calls. Add backend endpoints for activity feed and ensure all analytics reflect actual database state.

## Goal (from ROADMAP)
Backend: Endpoint for recent activity feed. Frontend: Replace static recent activity in DashboardPage. Frontend: Wire RFM/retention/revenue charts to real API.

## Decisions

### Dashboard Scope: KPI + Orders Only
- Dashboard shows: KPI cards (active orders, completed today, total clients, week revenue/expenses/profit), order status pie chart, weekly revenue bar chart, recent activity list
- RFM segments, retention line chart, revenue by service, marketing sources → move to AnalyticsPage
- Dashboard remains the "quick overview" page; AnalyticsPage is for deep analysis

### Recent Activity: Last Orders
- Recent activity feed shows last 10 work orders with: client name, service, status, total_cost, created_at
- Ordered by created_at DESC (or scheduled_date)
- Simple list, no complex filtering

### Retention: All-time Cohorts
- Retention analysis covers ALL historical data since first order
- Cohort grouping by first order month
- Return periods: 1 month, 3 months, 6 months, 12 months
- Show as percentage of cohort that returned

### Analytics API Consolidation
- Existing analytics endpoints (/rfm, /revenue, /retention, /sources) need to return real calculated data
- May need to optimize queries for performance (SQLite with ~1000s of records should be fine)
- Add caching if needed (but keep simple for now)

### Auth
- Do NOT add auth in this phase (Phase 1.4)
